# Smart One by One

## 调用边界

- 仅在用户显式调用 Codex 的 `$smart:one-by-one` 或 Claude Code 的 `/smart:one-by-one` 时启动。
- 每轮只处理一个最小 Cycle，同一时刻只保留一个当前 Cycle。
- 不建立完整 Cycle 地图，不创建或更新 HTML，不为后续 Cycle 生成持久化留痕。

## 核心流程

1. 没有当前 Cycle 时，读取仓库规则、相关代码和测试入口，选择最小的一个未完成行为。
2. 重新读取本轮涉及文件，确认没有未协调的并行变化。
3. Agent 只落盘本轮必要的最小 Red，不修改实现代码，并运行定向验证。
4. Red 必须因目标行为尚未实现而失败；失败原因不符时停止，只说明阻塞原因。
5. Red 符合预期时，不展示 Red 代码、修改步骤或完整日志。
6. 在同一次回复中给出 Green 人工落盘步骤、验证命令和预期结果。
7. 用户落盘 Green、运行验证命令并返回完整结果后，判断本轮是否通过。
8. 验证失败时保留当前 Cycle；验证通过后等待用户明确验收。
9. 用户明确回复“验收通过”后结束当前 Cycle；“继续”不算验收通过。

用户明确说“你修复”时改走代为修复路径；用户要求 Review 时改走 Review 路径。

## Green 输出

先用白话说明本轮单一行为，再依次给出涉及文件、准确人工落盘步骤、搜索自检、当前 Cycle
验证命令和预期结果。所有内容必须在同一次回复中完整给出。

### 人工落盘格式

- 文件只显示项目相对路径，禁止绝对路径、worktree 路径或 `file://` 链接。
- 给出可复制的准确搜索原文和预计匹配数量。
- 直接写“删除全部，替换为”，并给出完整内容；新增文件时给出完整文件内容。
- 说明修改后应匹配或消失的内容及预计数量。
- 不使用起点、终点、首个、上一个、上面或下面等相对定位。

### 代码表达与验证

- 先解释目的再给代码；`import` 不添加注释，逻辑注释放在对应代码上方。
- 新增或替换代码默认不超过 80 列；JSON 等格式的说明写在代码块外。
- 命令只验证当前 Cycle，并明确预期测试名、数量或关键输出。
- 区分用户执行的证据与 Agent 实际执行的证据。

## Review 与代为修复

- Review 只检查当前 Cycle；Findings 优先，并给出相对路径、准确行号、依据和影响。
- Review 不运行测试、不修改实现、不补做 Green。
- 代为修复前重新读取当前文件，不覆盖用户的新改动，只改已授权的当前 Cycle 范围。

## 验收门禁

- 用户明确验收通过前，不标记完成，不展示或执行下一 Cycle。
- 用户只说“继续”时，要求其明确确认“验收通过”。
- 不输出 `1`、`2` 选择菜单，不把历史授权延续到后续 Cycle。
