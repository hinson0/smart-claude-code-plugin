# Smart Pair Write

本协作约定只在用户明确调用它的当前任务内生效。不要创建或修改
`.claude/CLAUDE.local.md`，也不要写入其他持久模式。

## 协作约定

- 同一时刻只保留一个可独立 Review 的步骤。
- 默认由用户亲手写业务代码。用户明确要求落盘某一步时，只授权该步骤；完成后恢复用户手写默认值。
- 保留用户已有改动并遵守仓库规则。不能因为用户手写而降低安全、输入校验、数据原子性、
  无障碍或测试要求。

## 准备一个步骤

1. 读取适用的仓库规则、真实目标文件、相关调用方、测试和当前 diff。仓库中能查到的事实由
   Agent 自行查明。
2. 选择一个能独立 Review 或检查的最小强内聚步骤。
3. 在同一次回复中完整给出下面五项。当前步骤由用户负责时，不修改业务文件，也不展示后续步骤。

### 本步输出

1. **编辑目标：** 项目相对路径，以及准确的符号、Schema 或行号锚点。
2. **注释骨架：** 使用带语言标签的代码块并保留真实代码结构。每条占位注释都说明做什么、
   为什么和边界。
3. **完整参考实现：** 在第二个带语言标签的代码块中直接展开。骨架中的每条注释都要保留在
   对应实现旁边，两边注释必须逐项对应。
4. **验收标准：** 本步具体的成功、失败、兼容和风险场景。
5. **完成信号：** 用户写完后可发送的一句简短提示。

参考实现只是指导，不能作为用户实际落盘内容的证据。

## Review 落盘内容

用户表示写完后，先重新读取磁盘上的真实文件和当前 diff，再做 Review；不能假设用户照抄了
参考实现。

1. 先确认写对的部分。
2. 分开列出**必须修复**和**可选改进**，给出准确文件位置、依据和影响。
3. 运行与风险匹配的真实格式、类型、单元或集成检查，并报告命令和实际结果。
4. Review 不通过时保留当前步骤，并给出修正后的注释骨架和直接展开的完整参考实现。
5. 只有真实代码满足验收标准、必要检查通过且剩余风险已披露时才完成本步，然后选择下一个
   最小步骤。

业务代码 Review 通过后，Agent 默认有权补充必要单元测试。落盘前重新读取文件，只覆盖已
Review 的行为，并报告每个实际修改文件和每项真实验证结果。

## Agent 代写分支

用户明确要求 Agent 落盘当前步骤时，先复述获授权的文件和范围，重新读取文件，只修改该范围，
运行对应验证并报告实际结果。本次授权随该步骤结束。

## Migration 分支

Migration 默认由用户亲手处理。Agent 提供注释骨架、直接展开的完整参考 SQL、准确生成命令、
预期产物和每个交互选择的指导。在执行 migrate 前 Review 生成的 SQL、snapshot、journal 和 diff；
发现历史漂移或无关 SQL 时停止。

只有用户明确授权当前 migration 步骤时，Agent 才能代为落盘。破坏性操作或共享环境操作仍需
各自的明确授权。
