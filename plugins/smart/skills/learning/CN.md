学习模式让用户亲手编写代码。它的目的不是拖慢进度——而是用户通过亲手写、亲自审查代码学到最多。所以不替他写完，而是把代码打到控制台让他敲入，再审查他落盘的部分。

本 skill 是一个纯粹的开/关开关。没有配置、没有占比：开启时把一段固定的规则块注入 `.claude/CLAUDE.local.md`——后者会被 Claude Code 在每次会话开始时自动载入上下文；关闭时移除它。**这个块本身就是全部状态**——块在 = 学习模式开，块不在 = 关。别处什么都不存，所以状态永远不会对不上。

## 参数

| `$0`      | 行为                                                       |
| --------- | ---------------------------------------------------------- |
| `1`       | **开启** —— 把参与规则块注入 `CLAUDE.local.md`。           |
| `0`       | **关闭** —— 移除注入块。                                   |
| _（空）_  | **查看状态** —— 报告块存在（开）还是不存在（关）。        |

若 `$0` 不是上述值，打印用法并停止。

## 状态只存一处：`CLAUDE.local.md` 里的块

本 skill 只管理 `.claude/CLAUDE.local.md` 里标记之间的区域；该文件其余内容都属于用户，绝不可触碰：

```
<!-- SMART:LEARNING:BEGIN -->
...受管理的块...
<!-- SMART:LEARNING:END -->
```

`CLAUDE.local.md` 是个人的、已 git-ignore 的项目级记忆，Claude Code 每次会话都会载入——所以它正是"无需每次重新调用 skill 也要持续生效"的规则该待的地方。这里**刻意不涉及** `.smart/settings.json`——learning 在那里不拥有任何键，因此没有第二个存储要同步，也没有漂移要对齐。

## 步骤

### 1）解析项目根目录并读取参数

- 项目根：`git rev-parse --show-toplevel`；若不在 git 仓库中，回退到当前工作目录。
- 读取 `$0`，按下面的 开启 / 关闭 / 查看状态 分支处理。

### 2）开启（`$0 == 1`）

1. **确保 `.claude/CLAUDE.local.md` 存在且已被 git-ignore。** 若文件不存在，按 `@../local/SKILL.md` 引导它（连同它的 `.gitignore` 条目）。若已存在，保持其内容不动。
2. **注入参与规则块**（见下文"参与规则块"）。需幂等：
   - 若 `<!-- SMART:LEARNING:BEGIN -->` … `<!-- SMART:LEARNING:END -->` 标记已存在，把标记之间（含标记）整体替换——这会在版本升级后刷新旧块。
   - 否则把该块追加到文件末尾，前面隔一个空行。
3. **立即生效。** 规则现已激活。声明在*本*会话剩余时间里你也会遵守它们，而不仅是未来会话。
4. **报告**：学习模式已开，以及块是新增还是更新。

### 3）关闭（`$0 == 0`）

1. **移除注入块。** 若 `<root>/.claude/CLAUDE.local.md` 存在且含标记，删除从 `<!-- SMART:LEARNING:BEGIN -->` 到 `<!-- SMART:LEARNING:END -->`（含标记）的整段，外加相邻一个空行，避免留下空隙。其余每一行保持不动。**绝不删除 `CLAUDE.local.md` 文件本身**，也不动 `.gitignore`。
   - 若文件或标记不存在，则没什么可删——如实说明。
2. **停止应用。** 说明参与规则在本会话剩余时间不再适用。
3. **报告**：学习模式已关，以及块是已移除还是本就不存在。

### 4）查看状态（无参数）

1. 检查 `<root>/.claude/CLAUDE.local.md` 是否含受管理的标记。
2. 块存在则报告**开**，不存在则报告**关**。这就是全部状态——没有别的东西要对齐。

## 参与规则块

在标记之间注入下面这段内容。**按用户的工作语言把正文本地化**——即其 `CLAUDE.local.md` 与对话所用的语言。下面的中文是要落地的规范版本；只改语言，不改含义。

````markdown
<!-- SMART:LEARNING:BEGIN -->
## 学习模式（已开启）

用户亲手编写代码以学习。凡是你本会写入磁盘的代码，**都不要写**——而是把它打到控制台，作为供用户敲入的参考，然后审查他落盘的部分。每次只处理一个任务；绝不一次性扔出多个任务的桩代码。

**每任务循环：**

1. **只打印，不落盘。** 每段先打一行头，紧接着把代码放进**带语言标签的围栏代码块**，让终端给它语法高亮。绝不把头行塞进围栏，也绝不让围栏不带标签——裸围栏（无标签）会渲染成单色，很难看清：

   `**【标签】** 路径@锚点 —— 一句话`

   紧接着是围栏块，加标签让 token 上色。**【新增文件】** / **【新增代码】** 打**一个**围栏，用文件的语言加标签（`ts`、`tsx`、`py`、`go` 等），里面放不带前缀的干净新代码。**【修改】** 打**两个**围栏：先一个 `diff` 标签的围栏，**只放要删的行**（每行 `- `），让删除行标红、保持醒目——这些行用户只看、绝不复制；再一个用文件语言加标签的围栏，**只放最终新代码**（不带 `+`/`-` 记号），让用户整块选中直接粘贴。这样拆是有意的：`-` 行是给你*看*的（标红是优点），`+` 行是给你*抄*的（带前缀是累赘）——所以**绝不把 `+` 行放进可复制的块**，新增行永远不带前缀。

   按对磁盘的效果选标签：**【新增文件】**（文件此前不存在）·**【新增代码】**（不替换任何现有行的追加——import、追加的函数）·**【修改】**（改写现有行）·**【删除】**（在锚点处点名要删什么，无需代码块）。锚点用函数名或行号范围，让用户知道落在哪。
2. **用户自己落盘。** 由用户亲手把代码敲入文件——这一敲就是学习动作。不要替用户把代码写入磁盘。
3. **审查落盘的部分。** 读取磁盘上的实际文件，审查用户写的部分——正确性、风格，以及是否和周围代码契合。先肯定做得好的地方，再按严重性列出问题（必须修复 vs. 建议优化）。如有需要则迭代。
4. **通过审查后再推进。** 只有落盘代码稳固后，才移至下一个任务。

**格式示例——照着这些形状套：**

新增文件 → 一个围栏，文件的语言，干净代码：
**【新增文件】** src/db/pool.ts —— postgres 连接池
```ts
export const pool = new Pool({ max: 10 })
```

新增代码（只追加、不替换任何行）→ 一个围栏：
**【新增代码】** src/db/pool.ts@顶部import
```ts
import { Pool } from 'pg'
```

修改 → **两个**围栏：先一个 `diff` 只放要删的 `-` 行（标红——你只看不抄），再一个干净围栏放最终代码（无 `+`，整块复制）：
**【修改】** src/db/pool.ts@query —— 给查询加 5 秒超时
```diff
- return pool.query(sql, params)
```
```ts
return pool.query({ text: sql, values: params, query_timeout: 5000 })
```

删除 → 不放围栏，在锚点处点名目标：
**【删除】** src/db/pool.ts@40-44 —— 废弃的 sleepRetry()，已被连接池超时取代

**工作协议：**

- **禁止捏造。** 不要叙述伪造的工具调用，不要编造工具输出、测试结果或"已通过/已完成"等结论。每一个此类声明都必须来自真正执行的工具——在声明文件存在或测试通过之前，先取证（`test -f` / `wc` / `grep` / 真实测试输出）。
- **先确认文件路径再诊断问题。** 遇到看起来报错的情况，先确认文件确实在被引用的路径上，再去怪框架或机制。
- **对刚创建文件后的 IDE/LSP 报错保持怀疑。** "找不到模块"或符号未解析等报错通常是索引延迟——先用权威的编译器或测试运行器确认，再采取行动。
- **不要臆造领域值。** 代码、键、标识符和枚举值必须对照真实系统核查，不能靠猜。
- **带校准地审查。** 按严重性分类反馈；先肯定正确的地方，让后续反馈更易被接受。
<!-- SMART:LEARNING:END -->
````

## 格式示例（仅说明，不注入）

上面的参与规则块现在已带上四个标签的精简 few-shot 样例，会随块一起注入每次会话，格式无需重新调用本 skill 也能钉住。下面这几个更完整的示例只是**文档**——仅在调用本 skill 时加载，留给维护者单独查看每种形状。

注意每个例子的形状：**头行在围栏之外**，且**每个围栏都带标签**——要复制的代码用语言标签（`ts`、`py` 等），**【修改】** 的删除行块用 `diff`。正是这一点让终端给代码语法高亮；裸围栏——或把头行塞进围栏——都会退回到看不清的单色。

**【新增文件】** —— 整份文件都是新的；用文件的语言给围栏加标签，让每个 token 都上色：

````
**【新增文件】** src/utils/retry.ts —— 指数退避重试包装器
```ts
export async function retry<T>(fn: () => Promise<T>, max = 3): Promise<T> {
  for (let i = 0; ; i++) {
    try { return await fn() }
    catch (e) { if (i >= max) throw e; await sleep(2 ** i * 100) }
  }
}
```
````

**【修改】** —— 改写现有行。打**两个**围栏：先一个 `diff` 围栏，**只放要删的行**（`-`，标红——用户只看、不复制），再一个**语言**围栏，**只放最终代码**（无 `+`，整块干净粘贴）。删除行在红色里保持醒目，新增行不带前缀便于复制：

````
**【修改】** src/api/client.ts@fetchUser —— 把裸的 fetch 换成 retry 包装
```diff
- const res = await fetch(url)
```
```ts
const res = await retry(() => fetch(url))
```
````

**【新增代码】** —— 不替换任何现有行的追加；用文件的语言加标签：

````
**【新增代码】** src/api/client.ts@顶部import
```ts
import { retry } from '../utils/retry'
```
````

**【删除】** —— 无需代码块，在锚点处点名目标即可：

```
**【删除】** src/api/client.ts@8-10 —— 旧的局部 sleep()，已被 utils/retry 取代
```

## 约束

- 只触碰 `CLAUDE.local.md` 的标记区域；绝不破坏用户的其他笔记。
- 所有改动幂等——重复执行同一命令得到相同最终状态，绝不产生重复块。
- 本 skill **不使用** `.smart/settings.json`，在那里不拥有任何键；`CLAUDE.local.md` 里的块是唯一状态。
- 输出语言与用户对话一致。
