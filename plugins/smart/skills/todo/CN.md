# Todo —— 会话主线锚点

长对话会发散。用户停在某个决策上（「做 A 还是 B？」），问了个跟进问题，CC 就把一切重组成更长、改了名的清单——原来的决策被埋掉，用户也丢了「自己到底想干什么」的线头。本 skill 用一份持久文件 `.smart/todo-list.md` 对抗这种熵增：

- **钉住一条主线**——那唯一的根本目标——分支再怎么翻搅都冲不掉；
- **把分支停好**——CC 不断抛出的那些决策——并对账，让重复调用时是**合并进既有条目**、而非堆叠出一堆重复。

它的定位不是任务管理器，而是每次运行都**把用户拉回主线**——所以报告永远先重述主线。

## 文件：`.smart/todo-list.md`

每个项目一个固定文件（被 git 忽略——它是个人草稿状态，永不提交）。文件内容语言跟随对话。使用如下结构：

```markdown
# Todo · <短标签，如 learning-mode 代码 review>
<!-- 由 /smart:todo 维护 · 更新 <YYYY-MM-DD HH:MM> -->

## 🎯 主线（钉住 —— 勿被分支冲散）
> <一句话：根本目标>
- [ ] M1 <步骤>
- [x] M2 <已完成步骤>

## 🌿 分支（CC 发散出的决策 —— 待决岔路）
- [ ] B1 <决策标题>  ↳M1
  - 选项：A) …  B) …
  - 倾向：<倾向 + 理由>
  - 状态：🔵 未决
- [ ] B2 <决策标题>

## 🧊 低优先 / 冻结
- [ ] B3 <可批量收尾>

## ✅ 归档（已决 / 已废弃）
- ~~B0 <标题>~~ → 决策 A（<日期>）· <理由>
```

每个分支保留一个稳定 id（`B1`、`B2`……），并在有对应主线步骤时映射到它（`↳M1`）。稳定 id 让 `done <id>` 和对账都能可靠地引用条目。

## 模式

- `/smart:todo`（无参）——主手势。扫描当前对话中 CC 发散的决策，对账进文件，报告时主线优先。
- `/smart:todo main <目标>`——设定或替换主线。这是**唯一**能改动钉死主线的动作。
- `/smart:todo done <id>`——把某主线步骤（`M#`）标记完成，或把某分支（`B#`）移入归档并记录其决策。

## Step 1 —— 范围：读什么、什么算一个决策

读取**当前对话**（本会话的 user + assistant 消息）。**不要**扫源码里的 TODO 注释，也不要读原生的会话内任务列表——那是两回事。把 system reminder、原始 tool-call JSON、命令 stdout 当作噪声剔除。

从对话里，只抽取 **CC 发散出的决策**——那些让用户停下来、需要做选择的东西：

- 明确的二选一决策（如「回退单条注册 vs 修 Observer 层」）
- 分优先级的行动清单（必修 / 覆盖 gap / 低优先）
- 「你想先做哪个？」的提问与建议顺序

不要把每一句顺带提及或零碎小事都收进来——那种噪声正是用户想逃离的。一个决策只有在「选错会把工作带向另一条路」时，才配得上一个分支。

## Step 2 —— 载入或初始化

若 `.smart/todo-list.md` 存在则读取。

**首次运行（文件还不存在）：** 从对话**推断主线**——在所有分支底下、用户根本想达成的那件事——并用 `AskUserQuestion` 确认（「你的主线是不是 X？[是 / 我来改措辞]」）。**不要静默钉一条猜的主线**；它是锚，必须对。确认后，用确认过的主线 + Step 1 抓到的分支创建文件。

## Step 3 —— 对账（合并，别重写）

对 Step 1 的每个决策，**按语义而非字面**去对齐既有分支——同一个决策常常改了名、扩了写又冒出来，把它们收拢回同一条正是本 skill 的核心工作：

- **新增（new）**——没有既有分支匹配 → 用下一个 `B#` id 追加为新分支。
- **重复（duplicate）**——既有分支已覆盖它且无新信息 → 原样不动，计为「已在跟踪」。
- **差分（diff）**——匹配某既有分支，但多了新选项、新倾向或新理由 → 把新增部分**追加**到那个既有分支。不新建第二条，不覆盖旧文本。（一个稍后改名、补充细节后重现的决策，仍是**同一条**分支。）
- **推翻（overturned）**——对话推翻了之前的决策 → 保留旧条目，追加一段简短「更正」，并把它移入归档、记录新结果。

拿不准是 new 还是 diff 时，按 diff 处理——追加是可逆、安全的，而生出一条重复只会重造用户来这儿就是想摆脱的杂乱。

## Step 4 —— 写入

用对账后的内容重写 `.smart/todo-list.md`。护栏：**绝不删除分支。** 只追加分支、往里补内容、或改状态（未决 → 归档）。决策历史就是价值所在；把它悄悄丢掉就废掉了这个 skill。除非本次是 `main <目标>`，否则主线原样保留。

## Step 5 —— 报告（打印到对话，绝不落盘）

开头先给主线——这就是「把人拉回来」的时刻：

```
🎯 主线：<目标>  |  进度 M2✅ · 下一步 M1
本轮：扫描 N 决策 → 新增 X · 合并 Y · 已存在 Z · 更正 W
🌿 未决分支（建议顺序）：
  B1 <标题>（↳M1）— 选项 A/B，倾向 A
  B2 <标题>
👉 建议先定 B1（它卡着主线 M1）
```

保持紧凑。文件是记录，报告是把用户重新锚定的那一推。

## 护栏

- 主线**只**通过 `main <目标>` 改动——绝不作为对账分支的副作用被改。这是核心承诺：分支永远冲不掉主线。
- 绝不删分支——归档它们，让决策脉络存活。
- 抓发散出的决策，不抓每一件零碎小事。
- 作用于对话，不作用于源码里的 TODO 注释或原生任务列表。
- 报告打印到对话，不写进文件。
