# 单次推进一个 Cycle

## 状态模型

- 将一个完整的 Red → Green 视为一个 cycle。
- 将已经讲解并输出、等待落盘或审查的 cycle 视为“当前 cycle”。
- 始终最多保留一个当前 cycle。
- 没有当前 cycle 时，只输出第一个 cycle 并停止，不修改文件或运行命令。

## 教学流程

1. 输出当前 cycle 的目标、Red 测试、最小 Green 实现、验证命令和预期结果。
2. 等待用户选择当前 cycle 的完成方式：
   - 用户说 `next`：由 agent 落盘并执行当前 cycle 的完整 Red → Green。
   - 用户说 `review`：视为用户已经落盘并执行当前 cycle；agent 只读审查实际文件、差异和验证结果，不修改文件。
3. 当前 cycle 通过后，输出下一个 cycle 的完整教学内容，但不要落盘或运行它。
4. 立即停止，等待新的 `next` 或 `review`。

## next 路径

- 先落盘 Red 测试并运行，确认它因目标行为缺失而失败。
- Red 符合预期后，落盘最小 Green 实现并运行，确认 Green。
- 审查当前 cycle 的差异与验证结果。
- 只完成当前 cycle，不执行随后输出的下一个 cycle。

## review 路径

- 将 `review` 解释为用户已经完成当前 cycle 的落盘和执行。
- 只读检查实际文件、差异、Red/Green 证据和改动范围。
- 不修改文件、不运行修复、不代替用户补做 Green。
- 发现问题时停在当前 cycle 并说明，不输出下一个 cycle。
- 审查通过后输出下一个 cycle，但不要执行它。

## 执行边界

- 将每次 `next` 作为一次性授权，只执行当时已经展示的当前 cycle。
- `review` 不授权任何写入。
- 不把本次 `next`、写入许可、Docker 许可或其他工具许可延续到刚输出的下一个 cycle。
- 如果 Red 没有按预期失败，停止并解释差异，不实施 Green，也不输出下一个 cycle。
- 如果 Green 没有通过，停在当前 cycle 并报告证据，不输出下一个 cycle。
- 不在当前 cycle 中附带相邻测试、额外重构、格式化、文档迁移或下一验收项，除非属于 Green 不可分割的最低验证。
- 不因用户曾说过“后面你直接执行”而连续推进多个 cycle。

## 人工落盘定位

用户需要复制代码自行落盘时，每段代码都必须提供：

1. 准确文件路径；已知容器路径时同时提供容器内路径。
2. 可直接复制搜索的现有代码锚点，不能只描述“在某项检查结束后”或“在某方法里”。
3. 明确操作方式：插入到锚点之前、之后，或完整替换锚点。
4. 需要落盘的完整代码，不能只给局部提示。
5. 当前行号可以辅助说明，但不能替代代码锚点，因为行号可能变化。

如果锚点存在多处，扩大上下文直到它能唯一定位，或同时给出所属类、方法以及前后代码。

## Cycle 输出格式

输出下一个 cycle 时，依次说明：

1. 本 cycle 要证明的单一行为。
2. Red 测试的文件路径、可搜索锚点、落盘位置、完整代码、运行命令和预期失败。
3. 最小 Green 的文件路径、可搜索锚点、落盘位置、完整代码、运行命令和预期通过。
4. 明确声明该 cycle 尚未落盘，等待 `next` 或 `review`。
