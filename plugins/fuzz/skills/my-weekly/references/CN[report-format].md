# 周报格式

生成 `my-weekly` 报告时使用本文件作为输出结构和措辞的唯一事实源。

## 固定规则

- 标题同时显示仓库名和日期范围。
- 元数据使用“作者”和“周期”；周期写出开始时间、截止时间、自然周含义和时区。
- 正文标题固定为“本周完成”“提交统计”“提交依据”。
- “本周完成”按成果主题合并提交，不逐条复述 Git log。每个短 SHA 使用可点击的
  Markdown 链接；同一提交始终使用同一 URL。
- “提交统计”依次显示提交数、跨提交去重文件数、逐提交累计文本增删行数。
- “提交依据”按 committer timestamp 从早到晚排列，保留原始提交标题；每个短 SHA
  使用可点击的 Markdown 链接。
- 只有在修正先前已经交付的报告时，才在标题前写一行“校正”，说明旧值、正确值和原因；
  普通报告直接从一级标题开始。
- 无法安全推导 commit URL 时使用纯短 SHA，并在对应提交依据末尾注明
  “无法安全推导 commit URL”。

## 标准模板

```markdown
# <仓库名> 周报（<开始日期> 至 <截止日期>）

- 作者：<author email>
- 周期：<开始日期和时间> 至 <截止日期和时间>（<本周或 -N 对应自然周>，<时区>）

## 本周完成

- <按主题归纳的完成内容>（[`<短 SHA>`](<commit URL>)、[`<短 SHA>`](<commit URL>)）

## 提交统计

- 提交：<数量>
- 触及文件：<跨提交去重后的数量>
- 文本行数：+<逐提交累计新增> / -<逐提交累计删除>

## 提交依据

- [`<短 SHA>`](<commit URL>) <YYYY-MM-DD> — <原始提交标题>
```

## 空报告

没有匹配提交时保留标题、作者和周期，使用：

```markdown
## 本周完成

本周期没有匹配的非合并提交。

## 提交统计

- 提交：0
- 触及文件：0
- 文本行数：+0 / -0
```

省略“提交依据”，因为没有可引用的提交。
